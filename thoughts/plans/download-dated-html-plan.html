Download dated raw HTML plan exports

Add a one-click and CLI-accessible export path that produces a dated copy of a registered plan without the review shell. Plans without local image assets download as a standalone raw HTML file. Plans with required local image assets download as a portable zip containing one plan directory, the raw HTML file, and an assets/ directory with the copied non-HTML assets referenced by that HTML. While touching the review-shell action bar, also polish the existing navigator toggle into the same compact tool style.

Goal

Reviewers and plan authors can share a plan outside the local reviewer service by downloading a dated, portable artifact for email or file sharing. The downloaded artifact must be the plan HTML itself, not the review shell, source sync chrome, comments sidebar, or sanitized iframe wrapper. The same action-bar pass should make the existing plan navigator control visually consistent with the new download tool.

Solution narrative

Add a server-side export builder over the latest registered source version. The browser review shell gets a Download raw plan action that points at a binary download route. The same UI phase updates the existing desktop plan navigator toggle from a text button into a compact three-bars tool with accessible name and tooltip Plan Navigator. The CLI gets plan-review download <plan> for agents and operators. The route chooses the artifact type automatically:

  • No copied local image assets: return text/html; charset=utf-8 with a content-disposition filename such as download-dated-html-plan-2026-06-18-153012Z.html.
  • Copied local image assets present: return application/zip with a content-disposition filename such as download-dated-html-plan-2026-06-18-153012Z.zip. The zip contains download-dated-html-plan-2026-06-18-153012Z/download-dated-html-plan-2026-06-18-153012Z.html plus download-dated-html-plan-2026-06-18-153012Z/assets/<safe-asset-name>.

The HTML file in both formats is based on the stored source HTML blob for the selected plan version. For zip exports, local <img src> references that map to copied plan assets are rewritten to the packaged assets/ paths. Inline data images stay inline. Any asset-bearing reference in the scanner boundary that is not packaged, inline/self-contained, or explicitly excluded is non-portable and fails closed with an actionable error. That includes http:, https:, protocol-relative //, absolute path, and blob: references for images and non-image assets. Missing local image assets fail the same way because the product cannot honestly call those exports portable. Local non-HTML asset references that the product does not yet package, such as stylesheet/script/font/media references, fail closed with a clear unsupported-local-asset error instead of producing a silently broken share artifact.

UI mockup

The download action should live in the review shell's existing top action bar, not inside the rendered plan iframe. Use a compact icon-style download button with an accessible name and tooltip; the tooltip explains that it downloads the raw plan HTML, or a portable zip when assets are required. Show the navigator with the same compact tool treatment: a three-bars button with an accessible name and tooltip reading Plan Navigator. Place the download action near the index link and before heavier workflow actions so sharing the current source artifact is discoverable without looking in the comments sidebar.

Current implementation reality

Source and rendered blobs already exist

PlanReviewStore.registerPlan writes the original source HTML to html_blob_path and the sanitized review render to rendered_blob_path. getPlan() returns the latest VersionRecord with both paths.

Local image assets are already copied

discoverImageAssets and discoverSourceAssets collect relative local <img src> assets inside the plan directory. registerPlan stores copied assets in plan_assets, exposes them through listPlanAssets(version.id), and serves them through GET /assets/:assetId.

Review rendering rewrites images

renderPlan rewrites copied local images to /assets/<hash>, blocks external image URLs, leaves data/blob/asset URLs alone, and shows placeholders for missing assets. Export should not reuse the review shell, but it can reuse the image-source parsing and copied-asset manifest.

No raw download surface exists

The browser shell serves /p/:planId and the sanitized iframe uses /render/:planId. The CLI has register, index, show, and comment/queue commands, but no command or route that downloads the raw plan source as a dated standalone artifact.

No zip dependency exists

package.json has no archive library. Node 20 does not provide a built-in zip writer, so the plan locks a small dependency rather than implementing zip file structures by hand.

Test seams are available

src/__tests__/contracts.test.ts already covers rendering, asset discovery, API routes, and CLI behavior. src/test-fixtures/e2e-run.ts already exercises browser downloads/assets through Playwright-style flows and can verify the review-shell button.

Product intent alignment

  • Files stay authoritative: exports are built from the stored source HTML blob and copied source assets for the registered version, not from the browser shell or transient rendered DOM.
  • Golden path is obvious: a reviewer can click one browser action; an agent/operator can run one CLI command. The product infers artifact type from the registered version instead of asking users to choose html versus zip.
  • Safe default: missing, external, absolute, blob, or unsupported asset-bearing references fail closed with a clear next action instead of silently producing a broken or non-portable share package.
  • Surface parity: HTTP, CLI, browser UI, README, and tests define the same download naming, asset packaging, and error semantics.
  • Rendered-plan safety preserved: the export path does not weaken review-shell sanitization or source sync. It is a download of the authorial source artifact and its stored copied assets.
  • Action bar stays coherent: the adjacent navigator polish keeps the top action bar legible as compact tools instead of mixing one-off text and icon treatments.

Locked decisions

  1. Export the source HTML blob. The HTML artifact is the latest stored html_blob_path source for the plan version, not /render/:planId and not /p/:planId. This satisfies “raw html plan” and avoids review-shell chrome.
  2. Artifact format is automatic. HTML-only exports return a single .html; exports with copied local image assets return a .zip. No first-slice format picker is required.
  3. Zip layout is deterministic. The root directory and file basename are <slug>-YYYY-MM-DD-HHmmssZ. The HTML file is <root>/<root>.html; assets live under <root>/assets/.
  4. Use UTC download timestamps. Dated names use a UTC timestamp generated at export time so tests and agents do not depend on local timezone settings.
  5. Use the registered asset manifest and stored blobs. Export does not read arbitrary paths from the filesystem at request time. It packages only plan_assets rows for the selected version whose status is copied and whose blob path still exists. First-slice packaging covers copied local image assets discovered from <img src>; every other asset-bearing reference is scanned and rejected until the product deliberately supports packaging it.
  6. Rewrite only package-local image references. In zip exports, relative local <img src> values that map to copied assets are rewritten to assets/<safe-name>. Inline data:image/... values stay inline. Asset references outside supported <img src> packaging are not silently left behind; they are treated as unsupported assets and fail closed.
  7. Define the unsupported/non-portable asset scanner boundary. The export builder must scan the source HTML for asset-bearing references outside supported <img src> packaging. For every reference in this boundary, relative local references inside the plan directory are classified as unsupportedLocalSources; non-relative, external, protocol-relative, absolute-path, or blob: references are classified as nonPortableSources or externalSources. The first slice must include at least: srcset on <img> and <source>, <source src>, <video poster>, <object data>, <embed src>, <audio src>, <video src>, <track src>, <script src>, stylesheet/preload/icon <link href>, and url(...) references in style attributes and <style> blocks. Fragment-only links, navigational <a href> links, and explicitly self-contained values such as data: URLs stay out of the failure list.
  8. Fail closed for non-portable and unsupported asset references. Relative local image references without copied assets, unsupported local asset-bearing references, and non-relative/external/absolute/blob asset-bearing references in the scanner boundary return 409 export_not_portable with the offending sources and the next action to re-register/fix the source or remove unsupported/non-portable assets. This explicitly includes http:, https:, protocol-relative //, absolute path, and blob: references for images, scripts, stylesheets, media, object/embed refs, and CSS url(...) refs.
  9. Use fflate for zip creation. Add the zero-dependency, ESM-compatible fflate package instead of writing a custom zip implementation. Keep zip creation in a small server-side helper over buffers; plan exports are expected to be small repo artifacts, not large media archives.
  10. Add plan-review download <plan>. If --output is omitted, the CLI saves the content-disposition filename in the current directory and prints the path. --output <directory> always means an output directory; create it when missing and save the server-provided filename inside it. To avoid accidental data loss, fail with an actionable error when the resolved target file already exists; exact output-file paths and overwrite flags are not included in this slice.
  11. Place the browser action in the top review-shell action bar. The action should appear as a compact download icon link/button near the index/navigation controls and before planning-specific workflow buttons. It must include an accessible name Download raw plan plus a tooltip explaining that it downloads raw plan HTML, or a portable zip when assets are required. It must not live inside the rendered plan iframe or comments sidebar.
  12. Include the adjacent navigator polish. Because P3 already edits the review-shell action bar, this plan also updates the existing desktop navigator toggle to an icon-only three-bars control with accessible name and tooltip Plan Navigator. Do not redesign plan navigation behavior or mobile navigation in this slice.
  13. Do not export comments or screenshots. This feature exports the plan artifact for sharing, not the review thread or comment asset history.

Acceptance criteria

  1. A registered plan without copied local image assets can be downloaded from the browser and CLI as a dated .html file containing the raw plan source without review-shell markup.
  2. A registered plan with copied local image assets downloads as a dated .zip whose root directory contains one HTML file and an assets/ directory containing every supported copied local image asset required by the HTML.
  3. The HTML inside a zip rewrites packaged local image references to relative assets/<safe-name> paths, and unzipping the archive allows the HTML to load those supported images without the plan-review service running.
  4. Exports fail with a structured, actionable error when a plan version contains missing local image assets, unsupported local asset-bearing references, or external/absolute/blob asset-bearing references that would make the artifact non-portable.
  5. HTML and zip artifact names include the plan slug and a UTC YYYY-MM-DD-HHmmssZ timestamp, and content-disposition headers are safe for spaces and special characters.
  6. plan-review download <plan> uses the same service route and artifact selection as the browser button, writes the file to the requested output location, and reports the saved path.
  7. The review shell exposes a visible compact download button for planning and collaboration documents with accessible name Download raw plan and tooltip copy explaining raw HTML versus portable zip behavior, without disrupting comment selection, source sync reloads, or lifecycle buttons.
  8. The existing desktop plan navigator toggle is updated to a compact three-bars tool with accessible name and tooltip Plan Navigator, while preserving its collapse/expand behavior and state.
  9. README guidance documents the browser action, CLI command, automatic html/zip behavior, zip layout, and non-portable asset errors.

BDD scenarios

BDD-1: HTML-only plan download

Given a registered plan whose latest version has no copied local image assets, when a reviewer clicks Download raw plan or an operator runs plan-review download plan_123, then the response is text/html, the filename is dated, and the body is the raw plan source without review shell markup such as id="comments" or plan-frame.

BDD-2: Image plan zip download

Given a registered plan contains <img src="./diagram.png"> and the image was copied into plan_assets, when the plan is downloaded, then the response is a zip containing <root>/<root>.html and <root>/assets/diagram-<hash>.png, and the HTML references assets/diagram-<hash>.png.

BDD-3: Duplicate image filenames stay distinct

Given a plan references two different local images with the same basename from different relative directories, when a zip export is built, then both assets receive collision-safe names that include their asset hash and the HTML references the correct packaged path for each original source.

BDD-4: Missing local image fails closed

Given a registered plan source contains a relative image reference but the latest version has no copied blob for that source, when a user requests export, then the service returns 409 export_not_portable naming the missing source and advising the user to restore the asset and re-register or sync the source.

BDD-5: External image fails closed

Given a registered plan source contains <img src="https://example.com/diagram.png">, <img src="//cdn.example.com/diagram.png">, an absolute-path image, or any other image source that is not a relative path inside the registered plan directory and is not a data: URI, when export is requested, then the service returns 409 export_not_portable explaining that non-portable images cannot be packaged by the export and must be converted to local plan assets first.

BDD-6: Unsupported local non-HTML asset fails closed

Given a registered plan source contains a local asset reference that is not a supported <img src>, such as <img srcset="./wide.png 2x">, <source srcset="./wide.webp">, <video poster="./poster.png">, <object data="./diagram.svg">, <embed src="./diagram.svg">, <link rel="stylesheet" href="./plan.css">, <script src="./plan.js">, or style="background-image:url('./bg.png')", when export is requested, then the service returns 409 export_not_portable naming the unsupported local source and explaining that the asset must be inlined, removed, or covered by a later packaging slice. Given the same asset-bearing attributes use non-relative sources such as https://cdn.example.com/plan.css, //cdn.example.com/app.js, /assets/poster.png, blob:..., or url(https://cdn.example.com/bg.png), then the service returns 409 export_not_portable naming those non-portable sources instead of allowing a network-dependent export.

BDD-7: CLI saves the route response

Given the service returns a zip or HTML export with a content-disposition filename, when an operator runs plan-review download plan_123 --output ./exports, then the CLI creates ./exports as a directory if needed, writes the server artifact using the same filename inside that directory, and prints the absolute saved path. Given the resolved target file already exists, when the command runs, then it fails without overwriting the file and prints an actionable error.

BDD-8: Browser entry point downloads the visible version without comment side effects

Given the review shell is open on a displayed plan version, including after source sync has deferred or applied a newer frame version, when the reviewer hovers or focuses the compact download button, then the tooltip explains raw HTML versus portable zip behavior; when the reviewer activates the button with accessible name Download raw plan, then the browser starts an attachment download for the version currently displayed in the plan frame and no comment composer opens, selection state changes, or lifecycle action fires.

BDD-9: Navigator remains functional as a compact tool

Given the review shell action bar is visible, when the reviewer hovers or focuses the three-bars navigator button, then the tooltip reads Plan Navigator; when the reviewer activates it, then the existing navigator collapse/expand behavior and accessible expanded state still work.
