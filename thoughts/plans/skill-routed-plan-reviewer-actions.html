Skill-routed plan reviewer actions

Replace hardcoded browser action prompts with skill invocation requests, then add the matching shared skills to ai-configs so Pi and Codex listeners can execute them through their own native mechanisms.

Repo: plan-reviewer External config repo: ai-configs Linear issue: none supplied Status: validation-complete

Status

Implementation and scoped validation are complete. Browser action comments now route through named skills, ai-configs defines and installs those skills for Pi and Codex, and final GPT plus GLM scoped implementation rereviews returned PASS_SCOPED with no in-scope findings.

Goal

When a reviewer clicks Request execution-ready review or Build Plan in the plan-reviewer browser shell, the created agent-visible comment should ask the listening agent to use a named skill, not embed tool-specific review or execution instructions in plan-reviewer itself.

  • Request execution-ready review should call plan-reviewer-execution-ready.
  • Build Plan should call plan-reviewer-build with the plan path.
  • ai-configs should define and install both skills for Pi and Codex via the shared skill setup.

Why this plan exists

The current plan-reviewer service encodes agent choices directly in browser action comment bodies. That makes the service own decisions like “Codex plus Claude Code” or “run scoped-plan-run,” even though those choices belong in the active agent configuration. Moving this policy into skills keeps plan-reviewer focused on durable review/comment delivery while letting each listener choose the correct local execution strategy.

Solution narrative

Make plan-reviewer emit stable, minimal skill requests:

Use the plan-reviewer-execution-ready skill for this plan.
Plan path: thoughts/plans/example.html
Use the plan-reviewer-build skill for this plan.
Plan path: thoughts/plans/example.html

The skill documents in ai-configs become the source of truth for what those requests mean. For Pi, plan-reviewer-execution-ready runs read-only Pi subagent plan reviews using GPT and GLM. For build, plan-reviewer-build delegates to scoped-plan-run with the explicit plan path, preserving the current browser button outcome without hardcoding that command in the plan-reviewer service.

Product intent alignment

This plan advances thoughts/specs/product_intent.md by keeping plan-reviewer focused on durable plan registration, browser comments, and queue-backed delivery while making the agent’s required next action explicit. It removes hidden hardcoded reviewer policy from the service and places that policy in installable agent skills, which is a better source of truth for Pi/Codex behavior. The plan preserves the canonical comment lifecycle: browser action creates one pending comment, listeners claim it through the queue, and the listening agent processes only that requested action.

Locked decisions

  • Plan-reviewer will emit skill request language rather than Pi-only slash-command syntax so Pi, Codex, or future listeners can choose their own execution path.
  • Both browser action comments will include the registered plan path. The build skill requires it; the execution-ready skill benefits from the same explicit context.
  • The two new skills will be source-controlled in /Users/anichols/code/ai-configs/skills/ and added to skills/install-matrix.json for both pi and codex.
  • For Pi, plan-reviewer-execution-ready will run independent plan reviews with quality-reviewer (GPT) and quality-reviewer-glm (GLM, high/xhigh thinking where supported).
  • For Codex, plan-reviewer-execution-ready will use the existing Codex-native multi-review plan path from ai-configs, currently /review:plan <plan-path> followed by review integration, unless the skill detects that the active Codex install has a newer equivalent. Codex must not silently claim execution-ready if it cannot run or delegate two independent read-only plan reviews.
  • For Pi and Codex, plan-reviewer-build will delegate to scoped-plan-run with the explicit plan path rather than duplicating execution workflow rules.
