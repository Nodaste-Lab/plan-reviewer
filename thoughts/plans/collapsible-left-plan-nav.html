Implementation plan

Collapsible left-hand plan navigator

Add a top-left control that collapses and restores the existing left plan navigator so reviewers can temporarily use the full browser width for the rendered plan, while keeping the navigator expanded by default.

Goal

On desktop review pages at /p/:planId, the left-hand plan navigator should remain visible by default. A button at the top left of the plan-review toolbar should collapse the navigator out of the grid and expand the rendered plan area. Pressing the same button again should restore the navigator. The interaction should mirror the existing right comments toggle pattern: local page state, clear aria-expanded state, no default persistence, and no loss of comment/review behavior.

Why this plan exists

The left navigator is useful for moving between active plans, but long or wide HTML plans sometimes need more horizontal room. Reviewers should not have to open a separate route, zoom out, or rely on browser full-screen mode to focus on the plan body. A top-left collapse control gives an obvious “full width plan” mode while preserving the existing default navigator context.

Solution narrative

Add a desktop #desktop-plan-nav-toggle button as the first control in #plan-navbar-actions, before the Plan Index / Document Index link. The body starts without a collapsed class, so the navigator is expanded by default. Clicking the button toggles body.plan-nav-collapsed, updates aria-expanded and the accessible label, and lets CSS change the shell grid from 260px minmax(0,1fr) var(--comments-width) to 0 minmax(0,1fr) var(--comments-width). Mobile remains unchanged because the left navigator is already hidden in the mobile/coarse-pointer layout.

Full-width UI prototypes

These prototypes use the existing plan-review shell design: dark top toolbar, dark left/right chrome, compact pill buttons, the white rendered-plan iframe canvas, and the same collapsed right comments rail. They are intentionally full-width panels in this plan so reviewers can inspect the intended desktop proportions.

Product intent alignment

This plan advances thoughts/specs/product_intent.md by improving the browser reviewer’s golden path: reviewers can keep the active-plan navigator available by default, then intentionally enter a wider plan-reading mode without leaving the review shell. The change preserves durable comment behavior because it only affects shell chrome and does not alter comment creation, queue delivery, source sync, or rendered-plan sanitization.

  • Obvious workflow: the leftmost toolbar control affects the leftmost shell panel.
  • Safe default: the navigator stays expanded on every page load, matching the user request and preserving current discoverability.
  • Recovery: the same button restores the navigator; no hidden preference can strand a reviewer in collapsed mode.
  • Truthful status: aria-expanded, visible label/title, and shell layout stay in sync.

Locked decisions

  • The left navigator is expanded by default on desktop page load.
  • The collapse/expand button is the first control in the top toolbar, visually and DOM-order left of the index link.
  • The collapsed state is not persisted across page loads, matching the current comments toggle pattern and preventing surprising hidden navigation.
  • Mobile/coarse-pointer layout remains unchanged; #plan-list-nav stays hidden and no separate mobile left-nav drawer is introduced.
  • Plan switching still uses existing /p/:planId navigation; no client-side route reuse is added.

Acceptance criteria

  1. Desktop review pages render a top-left desktop-plan-nav-toggle button with aria-controls="plan-list-nav" and initial aria-expanded="true".
  2. On initial desktop load, the left plan navigator is visible at its current usable width and the current plan remains highlighted.
  3. Clicking the top-left button collapses the left navigator out of the grid, increases the rendered plan width, hides navigator content from sighted users and assistive tech, and updates the button state to collapsed.
  4. Clicking the button again restores the navigator, preserves the existing active-plan highlight, and updates the button state to expanded.
  5. The right comments toggle continues to work independently while the left navigator is expanded or collapsed.
  6. Existing plan commenting behavior remains intact: selecting plan content, showing markers, submitting comments, and rendering comments still work after collapsing/restoring the left nav.
  7. Mobile/coarse-pointer layout remains unchanged: no desktop left-nav button is shown, the left navigator remains hidden, and the existing mobile comments drawer still works.

BDD scenarios

Default desktop state

Given a reviewer opens /p/:planId on a desktop viewport, when the shell loads, then the left plan navigator is visible, the toggle reports aria-expanded="true", and the right comments panel remains collapsed by default.

Collapse and expand

Given the left navigator is visible, when the reviewer clicks the top-left nav toggle, then the navigator collapses and the plan iframe gains horizontal space. When the reviewer clicks it again, then the navigator returns with the same active plan highlighted.

Independent side panels

Given the left navigator is collapsed, when the reviewer opens and closes the right comments panel, then the left navigator remains collapsed until the reviewer explicitly restores it.

Comment precision after layout changes

Given a reviewer collapses or restores the left navigator, when they select a DOM section or view existing comment markers, then selection outlines and markers align to the rendered iframe content after the layout transition.

Mobile remains unchanged

Given a coarse-pointer or narrow viewport, when the shell loads, then the left plan navigator remains hidden as it does today, the desktop left-nav toggle is not displayed, and the mobile comments toggle remains the active drawer control.

Skip the listener when no marker comments or active selection overlays exist. Add the same transitionend-driven reflow to setCommentsOpen() for right-rail parity; this closes an existing overlay-latency gap exposed by this layout work.
  6. Keep the mobile media query unchanged except hiding the desktop left-nav toggle alongside the existing desktop comments toggle.
  7. Bump clientAssetVersion in src/server/app.ts, for example to left-nav-collapse-v1, so browsers invalidate cached shell CSS/JS.
