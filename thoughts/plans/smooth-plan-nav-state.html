Smooth plan navigator state

Goal

The left plan navigator must never visibly collapse and then re-open, or open and then collapse, during browser open, refresh, or navigation to another plan. If the navigator should be open, the review shell must render open on first paint. If it should be closed, it must render closed on first paint. After load, the left navigator should only collapse or expand when the user presses the plan navigator toggle button.

Decision Attention / Low-confidence Areas

No product decision required. The repo already has a configurable default for whether the plan navigator starts open, and the user request resolves the UX rule: no load-time state correction that changes layout after first paint.

Review focus resolved: the cookie-backed state is acceptable as the server-visible replacement for sessionStorage when scoped as a session cookie. It is local to this unauthenticated review service, stores only open or closed, and exists only to render the first paint correctly after the toggle is pressed.

Why this plan exists

The current client-side session state can disagree with the server-rendered body class. On a plan switch or refresh, the server sends one layout, then /client.js reads sessionStorage and calls setPlanNavOpen(...), which can change body.plan-nav-collapsed after the page is already visible. That layout correction is the jarring navbar collapse/re-open the user reported.

Authority and inputs

  • User request: sweep left navigator open/collapsed logic for browser open, refresh, plan change, and similar flows; no unnecessary collapses or changes; only the collapse/expand button should change state after load.
  • thoughts/specs/product_intent.md: browser review workflows should be obvious, smooth, and reliable without hidden tribal knowledge.
  • AGENTS.md and thoughts/plans/AGENTS.md: non-trivial UI changes in this repo need a reviewed HTML plan and product-intent alignment before execution.
  • src/server/app.ts: reviewShell() currently emits body.plan-nav-collapsed from configuration.showPlanNavigatorByDefault.
  • src/server/app.ts: /client.js currently reads/writes sessionStorage key plan-review:plan-nav-open and calls setPlanNavOpen(...) during startup.
  • src/test-fixtures/e2e-run.ts and src/__tests__/contracts.test.ts: existing tests cover default side-panel classes, toggle behavior, plan switching, and navigator presence.

Solution narrative

Replace client-only sessionStorage state with a small server-visible session cookie written only by the plan navigator toggle. The cookie is a rendering hint, not a durable preference system: use path=/, SameSite=Lax, no long-lived Max-Age, and only the literal values open or closed. The /p/:planId route reads that cookie and computes the initial left-nav state before rendering reviewShell(). When no valid cookie exists, it falls back to configuration.showPlanNavigatorByDefault. Client startup stops toggling the collapsed class; it only synchronizes inert/aria attributes to the class already present in the HTML. The toggle button remains the only runtime path that changes body.plan-nav-collapsed.

Product intent alignment

This plan advances thoughts/specs/product_intent.md by making the browser reviewer golden path calmer and more predictable. Reviewers should be able to open or switch plans without the shell moving under them, while still retaining a simple explicit toggle for full-width reading.

  • Obvious default: first paint reflects either explicit toggle state or the service configuration default.
  • Safe recovery: the same button changes the state and records it for the next server render.
  • Truthful status: aria-expanded, aria-hidden, inert, and body class are initialized from one computed state.
  • Bounded change: no queue/comment/source-sync/security behavior changes.

Locked decisions

  • The server-rendered body class is the first-paint source of truth for the left navigator.
  • A session cookie written by the toggle replaces sessionStorage because full page navigations need server-visible state to avoid flicker; it stores only open/closed and is not a durable preference.
  • When no explicit toggle cookie exists, configuration.showPlanNavigatorByDefault remains the fallback default.
  • After load, only #desktop-plan-nav-toggle may change body.plan-nav-collapsed.
  • Mobile/coarse-pointer layout remains unchanged; the desktop left navigator remains hidden there.

Acceptance criteria

  1. When the computed navigator state is open, /p/:planId responds without body.plan-nav-collapsed, with the toggle aria-expanded="true", and client startup does not collapse/re-open it.
  2. When the computed navigator state is closed, /p/:planId responds with body.plan-nav-collapsed, with the toggle aria-expanded="false", and client startup does not open/collapse it.
  3. The only runtime path that changes left-nav open/closed state is pressing #desktop-plan-nav-toggle; refresh and plan navigation preserve the already-rendered server state instead of correcting it after load.
  4. Switching plans through the navigator, quick open, or an in-plan /p/:planId link renders the next plan in the same computed navigator state on first paint.
  5. Collapsed/open states keep aria-expanded, aria-hidden, and inert synchronized without exposing hidden nav links to focus.
  6. Comments toggle, mobile layout, navigator filters, and rendered plan refresh behavior remain unchanged.

BDD scenarios

Open first paint

Given the computed navigator state is open, when a reviewer opens or refreshes /p/:planId, then the DOM is delivered open and no startup script toggles the body class.

Closed first paint

Given the computed navigator state is closed, when a reviewer opens or refreshes /p/:planId, then the DOM is delivered closed and no startup script toggles the body class.

Toggle affects subsequent pages

Given the navigator is open, when the reviewer presses the navigator toggle to close it and navigates to another plan, then the next review shell is served closed on first paint.

Toggle restores immediately

Given the navigator is closed, when the reviewer presses the navigator toggle, then the current page expands the nav, stores the open state for future review pages, and reflows overlays after the intentional transition.

Collapsed nav is inaccessible to focus

Given the navigator is collapsed, when script or keyboard navigation attempts to focus a navigator link, then focus does not enter the hidden navigator.
