Plan-reviewer HTML implementation plan

Kanban Card Right-click Status and Archive Menu

Add a custom context menu to Kanban board cards so a reviewer can right-click a card, move it directly to another visible board column, defer it with a note, or archive it without opening the plan detail page. The menu uses existing column and lifecycle APIs, preserves drag-and-drop, offers keyboard parity, and keeps failure recovery inline with the board.

Goal

Let users manage Kanban planning cards in place: right-click a card to choose another board column, defer the card with a required note, or archive the card immediately from the board, with clear success/failure state and no trip through the detail shell.

Decision Attention / Low-confidence Areas

  • No product decision required: the requested behavior maps cleanly to existing visible board columns and archive/unarchive/defer APIs. Defer from the menu must collect the same required note as the detail-shell Defer action.
  • Execution-readiness gates cleared: browser feedback is integrated, PM/product-intent review is ready, and independent GPT/GLM plan reviews returned execution-ready verdicts on 2026-06-25.
  • Scope guard: hidden columns are not shown in the Kanban context menu because the Kanban board intentionally omits hidden columns and their plans. Hidden-column movement remains available in the detail status selector.

Why this plan exists

The Kanban board already supports status movement through drag-and-drop, but drag can be imprecise for wide boards or trackpad use. The board also lacks direct defer and archive actions, forcing users to open a detail page or switch views. A right-click menu makes common card lifecycle actions discoverable to power users while preserving the existing drag and detail workflows.

UI impact: yes. This changes the Kanban board interaction model, adds a custom context menu, adds board-level defer and archive actions, and updates card movement feedback. The mocks below use the current dark plan-reviewer style: slate panels, blue focus/accent borders, pill badges, raised green Undo button, and top-right organizer error/toast placement.

Full-width UI mocks

It never covers the entire board and does not replace the existing detail link or drag-and-drop behavior. The full menu includes status choices, Defer plan, and Archive plan.

Product intent alignment

This plan cites and advances thoughts/specs/product_intent.md.

  • Golden path: users can change a planning card’s workflow status, defer it, or archive it directly where they already see the work.
  • Truthful state: after a status move, the card appears in the selected visible column and counts update; after defer or archive, the card leaves the active board.
  • Safe recovery: archive uses the existing undo-toast recovery pattern; failed moves and archive failures keep or restore the card and explain the retry path.
  • Fail-closed boundary: if Kanban is disabled, if a card is not a planning document, or if the service rejects a move/archive, the UI does not fabricate success.
  • Minimal hidden state: the menu uses the visible server-rendered board columns already present on the Kanban board.

Locked decisions

  • Use a custom HTML context menu opened by the card contextmenu event, not the browser-native menu, because the browser-native menu cannot call app actions.
  • Expose menu actions only on rendered Kanban cards for planning documents.
  • Include keyboard parity with focusable cards plus Shift+F10 and the Context Menu key.
  • Show only visible Kanban columns in the menu. Hidden columns remain manageable through configuration and the detail-shell status selector.
  • Reuse PUT /api/plans/:planId/column, POST /api/plans/:planId/defer, POST /api/plans/:planId/archive, and POST /api/plans/:planId/unarchive; no new API is required.
  • Defer from the menu must require a note/reason before calling the API, matching the existing detail-shell Defer behavior.
  • Preserve drag-and-drop as an equivalent movement path.

Acceptance criteria

  1. AC1: Right-clicking a Kanban card opens a context menu with visible board columns, Defer plan, and Archive plan actions.
  2. AC2: Choosing a different visible column calls the existing column endpoint, moves the card to that column after success, updates the card status badge and column counts, and closes the menu.
  3. AC3: Choosing the current column is a safe no-op that closes the menu without creating misleading UI state.
  4. AC4: If a column update fails, the card remains or returns to its previous column, counts are restored, and the board-level error explains that the move failed and can be retried.
  5. AC5: Choosing Defer plan prompts for the required note/reason, calls the existing defer endpoint after a non-empty note, removes the card from the active board after success, updates column counts, and does not archive the plan.
  6. AC5a: Choosing Archive plan calls the existing archive endpoint, removes the card from the board after success, updates column counts, and shows an Undo toast using the existing archive-toast interaction pattern.
  7. AC6: If defer or archive fails, the card remains visible and actionable, the menu closes, and the board-level error or toast reports what failed.
  8. AC7: The menu is accessible: cards can receive focus, keyboard users can open the menu with Shift+F10 or Context Menu, arrow through actions, activate with Enter/Space, and dismiss with Escape or outside click.
  9. AC8: Existing drag-and-drop movement and detail links continue to work.
  10. AC9: When Kanban is disabled, no new board context menu is exposed and existing movement API fail-closed behavior remains unchanged.
  11. AC10: Menu actions are single-flight per card: repeated clicks, Enter key repeats, or a drag start while a menu request is pending do not issue duplicate lifecycle calls or corrupt counts.
  12. AC11: If the card or destination state becomes stale while the menu is open, the board refreshes from server truth, closes the menu, and reports that the plan changed elsewhere instead of leaving a ghost card.
  13. AC12: The menu clamps or flips inside the visible board viewport near edges so every action remains visible and reachable without horizontal page scrolling.

BDD scenarios

Status change from context menu

Given the Kanban board is enabled and a planning card is in Backlog, when the user right-clicks the card and chooses In Progress, then the service receives PUT /api/plans/:planId/column with boardColumnKey: "in_progress", the card moves to In Progress, and Backlog/In Progress counts update.

Current column no-op

Given the menu is open for a Backlog card, when the user chooses Backlog, then the menu closes and the board does not show an error, duplicate the card, or change counts.

Move failure rollback

Given the menu opens for a Backlog card, when choosing In Progress receives a non-OK response, then the card is still in Backlog, counts are unchanged, and the board shows an actionable failure message.

Defer success with required note

Given the menu opens for a Kanban card, when the user chooses Defer plan, enters a non-empty reason, and the defer endpoint succeeds, then the card is removed from the active board, the column count decreases, and the plan appears in Deferred Plans with the note.

Defer cancellation

Given the menu opens for a Kanban card, when the user chooses Defer plan but cancels or submits an empty note, then no API call is made and the card remains on the board.

Archive success with undo

Given the menu opens for a Kanban card, when the user chooses Archive plan and the archive endpoint succeeds, then the card is removed from the active board, the column count decreases, and the archive undo toast appears.

Defer failure

Given the menu opens for a Kanban card, when Defer plan receives a non-OK response after a valid note, then the card remains visible, the menu closes, and the user sees a defer failure message with retry guidance.

Archive failure

Given the menu opens for a Kanban card, when Archive plan receives a non-OK response, then the card remains visible, the menu closes, and the user sees an archive failure message with retry guidance.

Keyboard parity

Given keyboard focus is on a Kanban card, when the user presses Shift+F10, moves with ArrowDown, and presses Enter, then the focused menu item activates the same action as a pointer click.

Drag remains supported

Given the new context menu code is present, when the user drags a card to another column, then the existing drag/drop move succeeds and no context menu opens during the drag.

Hidden columns are excluded

Given a board column is hidden in Kanban configuration, when the context menu opens for any visible card, then the hidden column label is absent from the menu and selecting a hidden destination is not possible from the board.

Kanban disabled fail-closed

Given Kanban is disabled, when a user right-clicks any plan row or card-like surface, then no Kanban card menu appears and no lifecycle endpoint is called from the board menu code.

Rapid activation is single-flight

Given the context menu is open and a lifecycle action has just been activated, when the user double-clicks, presses Enter repeatedly, or starts a drag before the request settles, then only one API request is sent, the card cannot be moved twice, and column counts stay consistent.

Stale card recovery

Given the menu is open for a card that is archived, deferred, deleted, or moved by another browser session before selection, when the chosen endpoint returns not found, conflict, or stale state, then the menu closes, the board refreshes from server truth, and a message explains that the plan changed elsewhere.

Viewport edge placement

Given a card sits near the right or bottom edge of a wide board, when the menu opens, then the menu clamps or flips into the visible board area so status options, Defer plan, and Archive plan remain visible and keyboard-reachable.
