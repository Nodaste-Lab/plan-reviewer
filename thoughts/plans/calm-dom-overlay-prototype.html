Replace the current full tinted hover/active highlight with an outline-only targeting surround that moves between DOM objects without a flash. The goal is a quieter Cursor-like interaction that still gives reviewers enough precision to attach comments confidently.

Clickable Prototype

Use the option tabs, then click target chips to move the surround between sample DOM objects. The movement is intentionally smooth and there is no full-page dimmer. In the review shell, clicks inside the plan are captured for DOM comments; use the direct rendered prototype at /render/plan_SFV1CW_Lsioe for interaction.

A: Cursor Dotted B: Corner Assist C: Settled Halo

A: Cursor Dotted

A light blue dotted outline with no floating label. This is closest to the user's requested Cursor model: no fill, no surrounding page tint, and no extra tab competing with page content.

  • Best fit when precision matters more than annotation branding.
  • Use for hover and active selection with only border weight changing on active.
  • Recommended default unless reviewers say it is too subtle.
Motion: 220ms ease on geometry, 140ms opacity only when entering/leaving the iframe.

C: Settled Halo

A solid outline with a very light static surround. It is the most visible of the three, intended for users who found dotted outlines too faint while still avoiding filled rectangles and page-wide dimming.

  • Best fit if contrast feedback says Options A or B disappear on complex content.
  • Active state can use the halo; hover can stay plain outline.
  • More assertive than the recommended default, but much quieter than today's overlay.

Reviewer note

Recommendation

Default: Option A

Ship the Cursor Dotted treatment first. It directly matches the requested model and removes the two flashiest behaviors: filled target tint and page-wide dimming.

Active Selection

Use the same surround for hover and selected state. Selected can use slightly stronger border weight, but it should not add a floating label or filled overlay. Clicking the surrounded object opens the comment dialog.

Existing Comments

Keep pending comment anchors visible, but convert their purple filled rectangles to a calmer outline variant so old comments do not recreate the same distraction.

Implementation Plan

Area Change Reason
.selection-box Remove the 0 0 0 9999px page mask, remove filled backgrounds, use outline-only border styles, and lengthen geometry transitions to roughly 200-240ms. The current page dimmer and filled boxes create the most visual churn while moving across DOM nodes.
.comment-anchor.pending Replace purple filled anchors with a dotted or dashed outline. Keep saved comment numbering separate from the live target surround so click targeting remains visually quiet. Existing pending comments should remain discoverable without becoming large tinted blocks.
positionSelectionBox Derive every live surround rectangle from the selected element's current getBoundingClientRect() after layout, then move one persistent overlay element between those measured rectangles. Avoid hard-coded offsets and avoid unnecessary hide/show cycles when the pointer moves from one valid target to another. Measured geometry is the only reliable alignment source across responsive wrapping, iframe scrolling, font rendering, and changed plan content.
Pointer movement Coalesce hover rectangle updates with requestAnimationFrame, and consider temporarily shortening or disabling geometry transitions during iframe scroll. The current mousemove path reads target geometry synchronously; a calm overlay should not trade flashiness for pointer or scroll jank.
Motion preference Add @media (prefers-reduced-motion: reduce) to disable overlay geometry transitions. Users who have reduced motion enabled should not receive animated target tracking.
Washi overlay Verify whether the mounted Washi read-only overlay is adding a second highlight layer. If so, disable or restyle that layer for DOM targeting mode. The user may be seeing stacked highlight systems, which would amplify flicker and distraction.

Acceptance Criteria

  • Hover and selected DOM targets have no tinted rectangular fill and no page-wide dimming mask.
  • The live hover/selected target surround has no floating label, tab, badge, or caption.
  • The live surround aligns to the exact current target rectangle on desktop and mobile, including after text wrapping, iframe scroll, and viewport resize.
  • Moving from one DOM object to another animates one surround between rectangles instead of flashing off and back on.
  • Clicking a surrounded DOM object opens the comment dialog for that object.
  • With prefers-reduced-motion: reduce, the overlay snaps without animated movement.
  • Pending and addressed comment anchors are visible but calmer than the current purple filled boxes.
  • Browser smoke verifies hover, click selection, composer open/cancel, iframe scroll, and mobile viewport behavior.

Decisions

  • Default visual direction: Option A, the light blue dotted surround.
  • Existing pending comments keep status separation with a distinct purple dotted outline, but no filled rectangle.
