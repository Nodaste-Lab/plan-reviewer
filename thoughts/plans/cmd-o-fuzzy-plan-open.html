Cmd-O fuzzy plan opener

Add a keyboard-first quick open overlay to the plan review browser shell so users can press ⌘O on macOS, type a fuzzy query, arrow to a plan, and open it without leaving the review page.

Goal

From any plan review page at /p/:planId, ⌘O opens a modal search palette that lists active plans as the user types. The user can navigate results with ↑/↓, open the highlighted plan with Enter, dismiss with Escape, or click a result with the mouse.

Solution narrative

Reuse the existing active-plan navigator data instead of creating a second server-side concept. The review shell already loads /api/plans/navigator?limit=200&currentPlanId=..., renders compact plan cards, and refreshes them periodically. This work should extend that client state into a keyboard palette: cache the current navigator payload in a module-level variable such as navigatorItems, score locally against title/repo/slug/path/status/issue/note terms, render the top ranked matches, and navigate to /p/:planId for the selected result.

Default workflow contract: users should not need to pre-open the left navigator, visit the index, or learn a CLI command. ⌘O from the review shell is the fastest safe path to another plan. On non-macOS browsers, Ctrl+O should also open the palette and prevent the browser's native file picker while the review shell has focus.

  • User request: add a quick open keyboard shortcut so Cmd+O opens fuzzy plan search, with typeahead matches and arrow-key or mouse selection, similar to Obsidian or web command palettes.
  • thoughts/specs/product_intent.md: plan reviewers need the simplest browser workflow to open, review, and move among plans without extra setup or tribal knowledge.
  • src/server/app.ts: reviewShell() renders the top toolbar, active-plan left navigator, plan iframe, and comments shell.
  • src/server/app.ts: client-side loadPlanNavigator(), renderPlanNavigatorItems(), and /api/plans/navigator already provide active-plan data and ordering.

Product intent alignment

This plan advances thoughts/specs/product_intent.md by making the browser reviewer easier to operate when many local plans are active. It supports the desired outcomes that reviewers can open local plans, plan authors can keep source-linked plans synchronized, and the plan index/review shell truthfully surface plan status.

  • Golden path: press ⌘O, type, select, open. No index detour or manual URL editing.
  • Safe defaults: search active plans from the same canonical navigator endpoint; opening a result navigates through the existing /p/:planId route, preserving current initialization and comment safety.
  • Recovery: if navigator data fails to load, keep the current plan reviewable and show an actionable inline palette error with a Retry action.
  • Fail-closed boundary: do not guess archived/deferred plans in quick open for this slice; active-plan search matches the current review shell navigator contract.
  • Regression focus: prove the keyboard shortcut and result selection in the actual browser shell, not just isolated helper functions.

Locked decisions

  1. Active plans only. Quick open searches the same active plan list as the left navigator. Archived/deferred search is out of scope until there is a product decision to include lifecycle-wide navigation.
  2. Client-side fuzzy scoring. Use the existing bounded navigator payload and score locally. No new endpoint is required for the first 200 active plans.
  3. Open by route navigation. Selecting a result sets window.location.href to /p/:planId rather than hot-swapping the active plan in place.
  4. Shortcut parity. Meta+O and Ctrl+O open quick open in the shell and prevent the browser file picker.
  5. No new dependency. Implement simple deterministic fuzzy matching directly in client.js because package size and matching needs are small. The expected primitive is a case-insensitive ranked match over normalized fields, using the field ordering in the fuzzy ranking decision.
  6. Simple ranked fuzzy matching. Rank exact/prefix title matches first, then title substring or ordered-subsequence matches, then repo/slug/status/note matches, and finally path-only matches; display a small top slice such as 10–15 results from the existing 200-plan navigator payload.
  7. Match the existing shell design. The quick-open affordance is keyboard-first and modal-only for this slice; do not add a permanent toolbar button or a new visual system that competes with the existing navigator/comments chrome.

Acceptance criteria

  1. Shortcut opens palette: pressing ⌘O on macOS or Ctrl+O elsewhere opens a modal quick-open palette from any review shell page, including when focus is inside the rendered plan iframe, and focuses the search input.
  2. Fuzzy matching: as the user types, results are filtered and ranked by plan title, repo, slug, path, Linear issue, status, progress, comments, and latest note terms using deterministic case-insensitive fuzzy scoring. Title exact/prefix/substring or ordered-subsequence matches rank above metadata matches, and path-only matches rank last.
  3. Keyboard selection: ↑/↓ moves the active result, Enter opens it, and Escape closes the palette without changing the current plan.
  4. Mouse selection: hovering or clicking a result updates/opens the selected plan with the same URL as the left navigator.
  5. Safe composer interaction: quick-open keyboard handling does not submit comments, discard in-progress comments, or trap the user when the comment composer is open.
  6. Navigator failure recovery: if navigator data is unavailable, the palette shows a non-destructive error and Retry control while leaving the current plan reviewable.
  7. Accessibility: the palette uses dialog/listbox semantics, exposes the highlighted option, returns focus on close, and has visible focus and active-result styling.
  8. Regression coverage: contract tests and e2e tests cover the shell markup, client shortcut behavior, fuzzy ranking, selection, failure recovery, and non-regression of existing comment shortcuts.

BDD scenarios

Open and select with keyboard

Given a user is viewing an active plan review page with multiple active plans registered, when they press ⌘O, type part of another plan title, press ↓, and press Enter, then the browser navigates to that plan's /p/:planId URL and the selected plan becomes the active review shell.

Fuzzy counterexample ranking

Given one plan title contains all query characters in order and another plan only matches a low-signal path segment, when the user types the query, then the title match ranks above the path-only match so the first highlighted result is predictable.

No matching plans

Given no active plans match the query, when the user types a nonsense string, then the palette shows an empty state, Enter does not navigate, and Escape closes the palette.

Comment composer remains safe

Given the comment composer contains unsent text, when the user opens and dismisses quick open, then the composer text remains intact and Cmd/Ctrl+Enter still submits the comment only when the palette is closed.

Shortcut works while the rendered plan has focus

Given focus is inside the same-origin rendered plan iframe after clicking or selecting plan content, when the user presses Cmd+O, then the parent review shell opens the quick-open palette, prevents the browser file picker, and focuses the palette input.

Navigator load failure

Given /api/plans/navigator returns an error, when the user opens quick open, then the palette explains that plans could not be loaded, offers Retry, and does not obscure the fact that the current plan remains reviewable.

Mouse selection parity

Given the quick-open palette is visible, when the user clicks a result row, then the browser opens the same URL that the left navigator link would open for that plan.

Mobile or coarse-pointer shell with hardware keyboard

Given the left navigator is hidden by the mobile/coarse-pointer layout, when the user presses Cmd+O with a hardware keyboard, then the palette still opens and fits the viewport.
