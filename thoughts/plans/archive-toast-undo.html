Plan-reviewer HTML implementation plan

Replace Archive Confirmation Prompts with Undo Toasts

Remove blocking browser confirmation dialogs from plan archive actions. Archive immediately, show an unobtrusive top-bar overlay toast with an Undo button for 10 seconds, dismiss the toast when the user resumes normal page interaction, and use the existing unarchive API to recover accidental archives.

Status: execution-ready Linear issue: none supplied Plan path: thoughts/plans/archive-toast-undo.html

Goal

Make archive actions feel reversible instead of interruptive: clicking Archive on an active plan archives it without a confirm popup, displays an unobtrusive top-of-screen toast with Undo for 10 seconds, and lets the user continue scrolling or interacting without being blocked.

Why this plan exists

The current browser confirm() popup blocks the reviewer workflow and forces a decision before the user can keep working. The desired interaction is a safer modern pattern: perform the action, offer a short undo window, and dismiss the recovery UI when the user moves on.

Product intent alignment

This plan advances thoughts/specs/product_intent.md by making the simplest reviewer workflow less interruptive while preserving recoverability. It keeps queue/source-sync semantics unchanged, uses the existing archive/unarchive lifecycle, and makes accidental archive recovery available directly in the browser UI without a blocking modal.

  • Golden path: Archive is one click and does not block page interaction.
  • Safe recovery: Undo uses the existing unarchive endpoint during a 10-second window.
  • Fail-closed boundary: If archive fails, the UI keeps the item actionable and shows an error; if undo fails, the toast reports that the plan remains archived.
  • Truthful state: Once archived, the active/deferred index removes the card, the review shell indicates archived/restorable state instead of pretending the plan is active, and active navigator/quick-open state is reconciled.

Locked decisions

  • No confirm dialogs for archive. Remove confirm() from archive actions on the active index and plan review shell; keep deferred archive prompt-free.
  • Undo window is 10 seconds. The toast auto-dismisses after 10 seconds and no longer offers recovery after dismissal.
  • Toast placement is top-bar overlay. The toast is compact and anchored near the top-right/top bar of the current page or viewer shell, not over the plan navigator/list and not as a bottom snackbar.
  • Undo is a prominent button. The Undo control uses a clearly clickable, high-contrast raised button treatment with sufficient padding and focus/hover states; it must not look like a quiet text link.
  • Normal interaction dismisses the toast. Scroll, pointer/click outside the toast, keyboard input, filter/search interaction, rendered-plan iframe scroll/click on desktop, or mobile review/touch-surface interaction dismisses the toast so the user can continue working.
  • Archive state reconciles navigation. Detail-page archive/Undo must refresh or locally reconcile the active plan navigator and quick-open cache so archived plans leave active navigation and Undo restores them.
  • Use existing unarchive API. Do not add a new archive transaction or delayed archive API; archive remains immediate and undo is a restore.
  • Do not redirect after detail-page archive. The review shell updates to archived state and shows undo instead of sending the user back to the index.

Acceptance criteria

  1. Clicking Archive on the active index, deferred index, or plan review shell does not open a browser confirm dialog.
  2. After a successful archive from any browser archive entry point, a compact top-bar overlay toast appears with clear archived text and a prominent high-contrast Undo button, without covering the plan navigator/list.
  3. Clicking Undo within the visible toast calls /api/plans/:planId/unarchive, restores the plan to active state, reloads/reconciles the current UI, and returns index, navigator, and quick-open state to a truthful active view.
  4. If no action is taken, the toast disappears after 10 seconds and the plan remains archived.
  5. If the user scrolls, clicks outside the toast, types in a filter/search field, scrolls/clicks inside the rendered-plan iframe, uses the mobile review/touch surface, or otherwise resumes interaction, the toast dismisses and the plan remains archived.
  6. Archive failure leaves the archive control usable and shows an inline or toast error; Undo failure leaves the user informed that the plan remains archived.
  7. Archive, unarchive, deferred, source sync, queue claiming, and rendered-plan safety contracts remain unchanged.

BDD scenarios

BDD-1: Active index archive shows undo without popup

Given an active plan card on the index, when the user clicks Archive, then no dialog appears, the card leaves the active list after the archive request succeeds, and a compact top-bar toast with a clearly clickable Undo button is visible.

BDD-2: Undo from index restores the plan

Given the index archive toast is visible, when the user clicks Undo, then the app calls unarchive, reloads the index from server-rendered state, and the plan is visible again as active.

BDD-3: Detail archive stays non-blocking

Given the user is reviewing a plan detail page, when the user clicks Archive, then no dialog appears, the page does not redirect to the index, the shell shows archived state, active navigator and quick-open entries are refreshed or locally removed, and the toast offers a prominent Undo button as a top-bar overlay that does not cover the plan navigator/list.

BDD-4: Deferred index archive has the same undo pattern

Given a deferred plan card, when the user clicks Archive, then no dialog appears, the card leaves the deferred list, and the same top-bar toast with Undo can restore the plan to active state through /unarchive.

BDD-5: Continuing work dismisses recovery UI

Given an archive toast is visible, when the user scrolls the page, interacts outside the toast, scrolls/clicks in the rendered plan iframe on desktop, or uses the mobile review/touch surface, then the toast disappears and the archived lifecycle state remains unchanged.

BDD-6: Failed archive or undo is explicit

Given archive or unarchive fails, when the user triggers the action, then the UI does not silently lose the plan and shows a concise error with the next safe action: retry Archive or restore from Archived plans.
