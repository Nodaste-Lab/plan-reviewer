Let rendered plan links remain clickable

Bug: the review shell captures every click inside the rendered plan iframe as comment intent, so clicking a normal anchor opens the comment composer instead of following the link. While hovering a link, the UI should not present a comment target; the reviewer should click nearby DOM text/container areas to comment on link-adjacent content.

Product intent

  • Native links work. A click or tap directly on an anchor/control inside the rendered plan must keep its normal browser behavior: fragment/default-target links may navigate the iframe, and target="_blank" links may open a new tab/window instead of being silently blocked by the review shell.
  • Comments remain easy around links. Clicking surrounding text or container DOM still opens the composer on the nearest plan node.
  • Hover communicates the boundary. When the pointer is over a link/control, no hover selection outline should imply that clicking will comment.
  • Keep scope narrow. Fix the event targeting contract; do not redesign comment mode, iframe rendering, or anchor sanitization.

Observed implementation

Global iframe click capture

src/server/app.ts attaches a capturing click listener to the rendered plan document. It always calls event.preventDefault() and event.stopPropagation(), then opens the element composer.

Target selection

commentTargetFromEvent resolves to the nearest [data-plan-node-id] or the raw element. Because render assigns data-plan-node-id broadly, anchors are treated as commentable plan nodes.

Hover outline

The iframe mousemove listener updates hovered for the event target without excluding interactive descendants, so anchors can show a comment affordance.

Implementation plan

  1. Write failing e2e coverage first. Extend the plan fixture in src/test-fixtures/e2e-run.ts with a separate link-specific section, not by changing the existing #dom-annotation section or Plan index target. paragraph, because later scenarios use exact-string replacements against those literals. Add an inline same-document anchor such as href="#link-target" next to normal text, plus a matching target element. Use page.frameLocator('#plan-frame') and a real Playwright pointer click on the anchor's rendered iframe coordinates, not a synthetic dispatchEvent, then assert the composer stays hidden and iframe.contentWindow.location.hash === '#link-target'. Assert anchor hover does not show a hover box after the deferred requestAnimationFrame reflow, and clicking adjacent non-link DOM still opens the composer.
  2. Add one interactive-target helper. In src/server/app.ts, add a small helper near commentTargetFromEvent that returns the closest interactive element with native/default behavior after sanitization: a[href], button, input, textarea, select, labels associated with controls, summary, and area[href]. Exclude role-only selectors such as [role="button"] or [role="link"] unless implementation also adds dedicated tests proving they are not dead zones in no-script rendered plans. Add a point-based variant for touch coordinates so touchend checks the same element that commentTargetFromPoint() would otherwise comment on.
  3. Respect the helper in mouse hover and click paths. In the iframe mousemove listener, clear hovered and reflow boxes when the target is interactive. In the iframe click listener, make the interactive guard the first branch, before preventDefault(), stopPropagation(), or suppressSyntheticClickUntil, so native clicks are not cancelled.
  4. Apply the same rule to touch. In touchstart, if the touch point is interactive, clear hovered and schedule a selection-box reflow so no stale hover affordance remains. In touchend, use the touch point to detect an interactive element before openElementComposer(commentTargetFromPoint(...)); return without opening the composer and without setting suppressSyntheticClickUntil for those taps.
  5. Permit native popup targets. Update the rendered plan iframe sandbox in src/server/app.ts from allow-same-origin to include allow-popups, so target="_blank" plan links are not silently blocked after the click interception fix. Keep scripts disabled and keep popups sandboxed; do not use allow-popups-to-escape-sandbox because same-origin SVG asset popups could otherwise escape the no-script sandbox.
  6. Verify behavior and regressions. Run build and e2e tests. Keep the primary click test deterministic with the in-fixture #link-target anchor rather than external navigation that could leave the review fixture. For target="_blank", use a real Playwright pointer click and a bounded popup assertion against a controlled same-origin http/https URL that survives sanitization, proving the sandbox allows the popup path without opening the composer.
  7. Give touch behavior credible coverage. Prefer adding a separate Playwright context with hasTouch: true and a real locator.tap() on the rendered link to assert composer remains hidden after the existing 120ms delayed touch path and the iframe reaches #link-target. If the environment cannot support a real touch context, use observable synthetic-event fallback coverage only: dispatch synthetic touch events on the link and assert the composer remains hidden after the delayed touch path, then deliberately dispatch a synthetic click/activation and assert the iframe reaches #link-target. Also assert adjacent non-link touch still opens the composer.

Proposed helper contract

function interactiveTargetFromEvent(event) {
  const rawTarget = event?.target;
  const element = rawTarget?.nodeType === 1 ? rawTarget : rawTarget?.parentElement;
  return interactiveTargetFromElement(element);
}

function interactiveTargetFromPoint(doc, event) {
  const touch = event.changedTouches?.[0] || event.touches?.[0];
  if (!touch) return interactiveTargetFromEvent(event);
  return interactiveTargetFromElement(doc.elementFromPoint(touch.clientX, touch.clientY));
}

The actual implementation should share the selector and target normalization with commentTargetFromEvent / commentTargetFromPoint so mouse and touch gates test the same DOM element that would otherwise become the comment target. Do not gate the mouseup text-selection path; selecting text that spans or includes link text is deliberate comment intent and should continue to open the composer. A linked image inside <a> should follow the link rather than opening the image comment lightbox; users can comment on surrounding DOM or the standalone image when it is not link-wrapped.

BDD scenarios

Scenario: clicking a rendered link

Given a rendered plan contains a same-document link such as <a href="#link-target">Example</a>, when the reviewer clicks the link text with a real Playwright pointer click on the anchor's rendered iframe coordinates, then the review shell does not open the comment composer and the iframe reaches #link-target.

Scenario: hovering a rendered link

Given the pointer is over a rendered link, when the hover handler runs, then the hover selection box is hidden and no comment affordance appears over the link.

Scenario: commenting near a link

Given a paragraph contains text before and after a link, when the reviewer clicks adjacent non-link text or the paragraph area, then the composer opens on the nearest plan node as it does today.

Scenario: tapping a rendered link on mobile

Given a touch device viewport, when the reviewer taps a rendered link, then touch handling does not open the comment composer or suppress the synthetic click.

Scenario: opening a target-blank link

Given a rendered plan contains a link with target="_blank" to a controlled deterministic URL, when the reviewer clicks the link with a real Playwright pointer click, then a bounded Playwright popup assertion observes the browser's new-tab path, the review shell does not open the composer, and scripts remain disabled.

Acceptance criteria

  • Anchor clicks inside rendered plans are not intercepted by comment creation.
  • Hovering over an anchor/control hides the comment hover selection box.
  • Clicking non-interactive DOM around a link still starts a comment.
  • Touch taps on links have credible coverage: preferably a real hasTouch Playwright locator.tap() verifies no composer after the delayed touch path and navigation to #link-target; otherwise observable synthetic-event fallback coverage verifies link touch leaves the composer hidden after the delayed path, a deliberate follow-up click/activation reaches #link-target, and adjacent non-link touch still opens the composer.
  • target="_blank" plan links are not silently blocked by the iframe sandbox after the event-layer fix.
  • bun run build and bun run test:e2e pass.
