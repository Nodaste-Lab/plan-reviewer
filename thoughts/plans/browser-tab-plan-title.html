Implementation plan

Show the plan name in browser tab titles

Make each plan review tab identify the plan being viewed, so users can distinguish multiple open review tabs without selecting them one by one.

Goal

When a user opens /p/:planId, the browser tab title should show the viewed plan's human-readable title/name instead of an opaque internal ID such as Plan plan_abc123. If the plan source title changes through live source sync, the already-open tab title should update with the refreshed plan content.

Why this plan exists

Plan reviewer users often keep several plan tabs open. The current parent review shell title is based on the generated plan ID, which makes tab switching harder because browser tabs do not expose the plan's title or slug.

Authority and inputs

  • User request: show the name/title of the plan in the browser title when viewing a plan.
  • README.md: review pages render sanitized plan HTML in a no-script iframe, and open pages reload the iframe after source sync.
  • src/server/app.ts: reviewShell() currently emits <title>Plan ${planId}</title>; /p/:planId calls that shell; client refresh code parses new rendered HTML but does not update the parent document title.
  • src/render/render.ts: the sanitizer allows <title> and preserves plan-authored titles in rendered HTML.
  • src/__tests__/contracts.test.ts and src/__tests__/helpers.ts: sample fixture title is Sample Plan, and renderer contract coverage already asserts it survives rendering.

Product intent alignment

  • Golden path: users open plan review URLs exactly as they do today; the tab title is automatically useful with no extra flags or manual naming.
  • Safe default: prefer the authored plan <title> because it is already part of the reviewed artifact; fallback to repoName / slug when title is missing or blank.
  • Self-healing: if the plan source title changes and source sync publishes a new version, the open tab updates during the normal iframe refresh path.
  • Fail closed boundary: if rendered HTML cannot be read or title extraction fails, keep the page usable and fall back to metadata instead of failing the review page.
  • Actionable errors: no new user-facing error path is needed; this is display metadata only.

Locked decisions

  • Title source: use the latest rendered HTML document title when it is non-empty after whitespace normalization.
  • Fallback: use ${repoName} / ${slug} when the rendered title is unavailable, blank, or extraction fails.
  • Tab format: format the parent shell title as <plan title> · Plan Review, avoiding a duplicate suffix if the title already ends with Plan Review.
  • No persistence change: do not add a plan title column or expand registration API contracts; this can be derived from already-stored rendered HTML.
  • Rendering contract: do not change sanitizer title preservation except through tests if a bug is discovered.

Acceptance criteria

  • AC1: Loading /p/:planId for a plan whose HTML contains <title>Sample Plan</title> returns a shell whose parent <title> is Sample Plan · Plan Review.
  • AC2: Loading /p/:planId for a plan without a usable HTML title returns a shell title based on repoName / slug, suffixed with · Plan Review.
  • AC3: When a live-linked plan syncs a new version with a different HTML title, an already-open review tab updates the parent browser title during the existing refresh flow.
  • AC4: Existing rendering, comments, archive/restore, source-sync warning, and registration contracts continue to pass without API or schema changes.
  • AC5: Special characters in plan titles are escaped in server-rendered shell HTML and do not create markup or script execution.

BDD scenarios

BDD1: authored title appears in tab

Given a registered plan HTML document has <title>Sample Plan</title>, when the reviewer opens /p/:planId, then the browser tab title reads Sample Plan · Plan Review.

BDD2: missing title falls back to known metadata

Given a registered plan has no title or a blank title, when the reviewer opens /p/:planId, then the tab title uses repoName / slug · Plan Review so the tab is still distinguishable.

BDD3: title text is safe

Given a registered plan title contains characters such as <, &, or quotes, when the parent shell is rendered, then the title is escaped as text and cannot inject shell markup.

BDD4: live refresh updates tab title

Given a live-linked plan tab is open, when source sync publishes a new rendered version whose document title changed, then the iframe refresh completes and the parent document.title updates to the new title without requiring a full page reload.

BDD5: render read failure does not block review shell

Given title extraction cannot read or parse rendered HTML for an otherwise valid plan, when /p/:planId renders, then the shell still opens with the metadata fallback title.
